📋 THE PROBLEM
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

You reported: "I don't see locally but wet land parameters"
- The drainage class indicator wasn't showing in wetland assessments
- SSURGO was returning valid drainage data BUT it wasn't being detected


🔍 ROOT CAUSE (FOUND)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The code only checked the FIRST drainage class:

    OLD CODE:
    ┌─────────────────────────────────────────────────┐
    │ dominant_drainage = drainage_classes[0]          │
    │                    ↑ ONLY FIRST VALUE!           │
    └─────────────────────────────────────────────────┘

SSURGO returns multiple soil components, each with different drainage:
    ["Moderately well drained", "Somewhat poorly drained", "Well drained"]
     ↑ First one checked        ↑ Would be missed        ↑ Not checked
     
If "Moderately well drained" came first, the code would miss the poorly-drained 
soils that WERE present in the field.


✅ THE FIX
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Changed to check if ANY component has poor drainage keywords:

    NEW CODE:
    ┌──────────────────────────────────────────────────────────┐
    │ 1. Get all drainage values (not just first)               │
    │ 2. Calculate mode (most common) for display               │
    │ 3. Loop through ALL values checking for:                  │
    │    "poorly", "poor", "somewhat poor" keywords             │
    │ 4. If ANY match found → set has_poor_drainage = True      │
    │ 5. Pass appropriate value to assessment                   │
    └──────────────────────────────────────────────────────────┘

RESULT: Now correctly detects poorly-drained soils even if not first in list
